# AI mistakes

One line per mistake an AI assistant made: date, what went wrong, and the fix.

- 2026-11-14 (Backend, A1): ran `npm run db:migrate` expecting `.env.local` to win, but drizzle-kit loads `.env` itself (bundled dotenv) before `drizzle.config.ts`, so the migration went to the database in `.env` (127.0.0.1:5433) instead of the local one. The eight new tables were empty; they and the `drizzle` schema were dropped at once, restoring that database. Fix: pass `DATABASE_URL` in the shell when running drizzle-kit, until drizzle.config.ts is fixed.
- 2026-11-14 (Backend, A1): fixed. `drizzle.config.ts` now gives `.env.local` precedence over `.env` even though drizzle-kit preloads `.env`: a variable counts as set by the shell only if it is in the original process environment (`/proc/self/environ`), otherwise `.env.local` wins. Checked through the real drizzle-kit CLI: with both files it resolves to the `.env.local` database; a shell `DATABASE_URL` still wins.
- 2026-11-14 (Orchestrator): the location picker treated empty coordinate inputs as `0` because `Number("") === 0`, so missing locations opened at the Gulf of Guinea instead of the configured demo center. Fix: require non-empty latitude and longitude strings before treating a complaint as already located; Playwright verified the center click returns `-1.288703, 3.815002`.
- 2026-11-14 (Orchestrator): initially carried forward the user’s mistyped Kenya longitude `3.815`; corrected the default center to Nairobi-region longitude `36.815` and verified the fresh page center directly in Playwright.
- 2026-11-14 (Orchestrator): migration `0007_complaint_workflow.sql` could not be applied. It added `complaint_status` values and used them in the same transaction (Postgres 55P04; drizzle-kit runs all pending migrations in one transaction), and when it was renumbered from 0004 during the merge its journal `when` stayed older than 0004–0006, so drizzle-kit would skip it on any database that already had 0006. The app read failed with only `[data] read_failed` because the server's database lacked the new columns. Fix: the index predicate calls an IMMUTABLE helper `complaint_status_is_active` instead of naming the new values, and the journal `when` now follows 0006.
