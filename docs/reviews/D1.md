## What must be updated after S6 (checklist)
Whoever owns S6 or D3 ticks these off and links the PR.

- [ ] **`reports` field names and types:** `location_text`, `water_point_type`, `problem`, `people_affected`, `serves_school_or_clinic`, `duration`, `caller_confirmed`, `summary`, `language_spoken`, `transcript`. These came from spec section 8 and the provisional `lib/domain/types.ts`, not from Vapi. Where and how these fields arrive is spec unknown 1.
- [ ] **Required columns vs. missing data:** `location_text`, `water_point_type`, `problem`, `duration` are NOT NULL. Red lines 6 and 7: a missing field must not crash the endpoint, and a report must never be silently dropped. The enums have `unknown`, but `location_text` has no fallback. Decide whether the columns become nullable, or D3 stores a documented placeholder and flags `needs_review`.
- [ ] **Call identity and duplicates:** there is no column for the provider's call ID, so a retried webhook (spec unknown 4) can't be recognised. Add a provider call ID (or a hash of it), unique per organization, once the payload shows what Vapi sends. It must not be personal data.
- [ ] **Allowed values:** check `problem`, `duration`, `water_point_type` and `channel` against what the assistant actually extracts (Phone / AI Prompter conforms to Backend's names, but confirm with the sample).
- [ ] **Transcript:** redaction and retention are still open (spec unknowns 2 and 10). The column holds plain text. Security decides before real calls are stored.
- [ ] **`complaints`:** recheck the report-to-complaint link, report count, and duplicate merging once D4 and D5 are designed against real reports.
- [ ] **`lib/domain/types.ts` and `docs/contracts-swap-plan.md`:** update to the final names in the same PR.
- [ ] **`docs/contracts.md`:** S6 replaces the provisional tables section and removes the PROVISIONAL marking.
