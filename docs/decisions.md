# Decisions

One line per real team decision: date, decision, and why.

- 2026-11-14: Self-host the stack. A Next.js app and a PostgreSQL database run on one team server instead of Vercel and Supabase. Only the Next.js server is public, on one port, through a Cloudflare Tunnel. Postgres is never exposed. Sign-in moves from Supabase Auth to an auth library that stores data in our Postgres (default: Better Auth). Live updates move from Supabase Realtime to our own API (default: polling). Why: full control over hosting and data, one public port, and no third-party data provider. Trade-offs: the team owns uptime, backups, and server-side permission checks.
- 2026-11-14: On the host server, the Next.js app listens on port 6543 (localhost). The existing Cloudflare Tunnel maps the public hostname bg.verilen.com to it, so no extra tunnel setup is needed. Postgres stays on 127.0.0.1:5433. Why: reuse an existing tunnel route and avoid ports already in use on the host.
- 2026-11-14: Developers can run Postgres locally without Docker through `npm run db:local`, which uses the `embedded-postgres` dev dependency (real Postgres 17 binaries from npm, version pinned to 17.11.0-beta.19) with data in a gitignored `.pgdata/`. Docker (`npm run db:up`) stays an option for developers and remains the only way the database runs on the host server. Why: teammates shouldn't need Docker to develop, and development should use the same Postgres as production (PGlite was rejected because it would need a separate dev-only driver). Trade-offs: one dev dependency that downloads about 30–50 MB, and its releases are tagged beta.
- 2026-11-14: Login and roles (task A1) start before S6, because they don't depend on the Vapi payload. Backend data work that needs the payload (water points, reports, complaints) still waits for S6. Vapi tasks belong to another developer. Decided by: the humans.
- 2026-11-14: Sign-in uses Better Auth with email and password, and sign-up is disabled. Accounts come only from the seed script. Decided by: the humans (the default in AGENTS.md; this answers spec AC-1 and section 12, decision 2).
- 2026-11-14: Staff sessions last 12 hours (one config value). Options were 12 hours (Security) or 7 days (the auth-prep proposal). Decided by: the humans.
- 2026-11-14: Org Admins get explicit region assignments, like every other role, not every region in the organization automatically. Why: one rule for all roles and no special case in the access check. Decided by: the humans.
- 2026-11-14: A1 builds only the accounts data and the Better Auth server. The session checks and the sign-in screen belong to the teammate's `feat/auth-prep` branch. Why: Frontend's dissent in gate attempt 1 (see `docs/reviews/A1.md`).
- 2026-11-14: The team develops on the production host, in dev mode. Development uses `.env.local`, `npm run dev`, and the `npm run db:local` database (127.0.0.1:5434). The Docker database `ihack26-db-1` on 127.0.0.1:5433 (named in `.env`) is production. No one runs `db:migrate`, `db:seed`, or tests against it without a human's OK. Why: an agent's migration reached the production database by mistake (see `docs/ai-mistakes.md`). Decided by: the humans (dev mode); the Orchestrator added the guard.
