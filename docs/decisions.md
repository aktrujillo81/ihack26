# Decisions

One line per real team decision: date, decision, and why.

- 2026-11-14: Self-host the stack. A Next.js app and a PostgreSQL database run on one team server instead of Vercel and Supabase. Only the Next.js server is public, on one port, through a Cloudflare Tunnel. Postgres is never exposed. Sign-in moves from Supabase Auth to an auth library that stores data in our Postgres (default: Better Auth). Live updates move from Supabase Realtime to our own API (default: polling). Why: full control over hosting and data, one public port, and no third-party data provider. Trade-offs: the team owns uptime, backups, and server-side permission checks.
- 2026-11-14: On the host server, the Next.js app listens on port 6543 (localhost). The existing Cloudflare Tunnel maps the public hostname bg.verilen.com to it, so no extra tunnel setup is needed. Postgres stays on 127.0.0.1:5433. Why: reuse an existing tunnel route and avoid ports already in use on the host.
- 2026-11-14: Developers can run Postgres locally without Docker through `npm run db:local`, which uses the `embedded-postgres` dev dependency (real Postgres 17 binaries from npm, version pinned to 17.11.0-beta.19) with data in a gitignored `.pgdata/`. Docker (`npm run db:up`) stays an option for developers and remains the only way the database runs on the host server. Why: teammates shouldn't need Docker to develop, and development should use the same Postgres as production (PGlite was rejected because it would need a separate dev-only driver). Trade-offs: one dev dependency that downloads about 30–50 MB, and its releases are tagged beta.
- 2026-11-14: Add a temporary `POST /api/vapi/capture` route (task S5a) that checks the Vapi shared secret and saves raw call bodies to the gitignored `docs/samples/raw/`. Why: the contract must be written from a real payload, and nothing else can receive one yet. A public webhook-inspector site was rejected because it would see the caller's phone number. The route is removed when the real Vapi endpoint (D3) lands.
- 2026-11-14: Keep the D1 schema (`feat/database-migrations`) even though it was built before S6. The tables that depend on the Vapi payload (`reports`, and the report link in `complaints`) are provisional and **must be updated after S6**. The checklist is in `docs/reviews/D1.md`. Options were to keep it marked provisional, merge it without `reports`, or discard it. Decided by: the humans.
- 2026-11-14: Login and roles (task A1) start before S6, because they don't depend on the Vapi payload. Backend data work that needs the payload (water points, reports, complaints) still waits for S6. Vapi tasks belong to another developer. Decided by: the humans.
- 2026-11-14: Sign-in uses Better Auth with email and password, and sign-up is disabled. Accounts come only from the seed script. Decided by: the humans (the default in AGENTS.md; this answers spec AC-1 and section 12, decision 2).
- 2026-11-14: Staff sessions last 12 hours (one config value). Options were 12 hours (Security) or 7 days (the auth-prep proposal). Decided by: the humans.
- 2026-11-14: Org Admins get explicit region assignments, like every other role, not every region in the organization automatically. Why: one rule for all roles and no special case in the access check. Decided by: the humans. **Superseded** by "A1 adapts to D1" below: D1 gives each user exactly one region.
- 2026-11-14: The team develops on the production host, in dev mode. Development uses `.env.local`, `npm run dev`, and the `npm run db:local` database (127.0.0.1:5434). The Docker database `ihack26-db-1` on 127.0.0.1:5433 (named in `.env`) is production. No one runs `db:migrate`, `db:seed`, or tests against it without a human's OK. Why: an agent's migration reached the production database by mistake (see `docs/ai-mistakes.md`). Decided by: the humans (dev mode); the Orchestrator added the guard.
- 2026-11-14: Expired staff session rows, which hold staff IP and user agent, are deleted when they expire, not kept. Options were 7 days, at expiry, or decide later. Decided by: the humans (Security review finding 7 on A1).
- 2026-11-14 (S4): Vapi call limits are 120 seconds maximum and 20 seconds of silence. Options were 90 or 120 seconds. Why: 90 would cut off slow callers during the read-back. A capped call costs about $0.18 at most. Set by: Andrew (Phone / AI), recorded in `docs/vapi-prompt.md` and `docs/budget.md`.
- 2026-11-14 (S4, S5): Extraction uses Vapi's Structured Output named `water_point_report` (nine fields, all required), not the older analysis plan. The server must find it by name, because its ID differs per Vapi account. Why: it is what the live assistant produces; calls 1 and 2 showed that an assistant without it sends no extracted data at all. Set by: Andrew.
- 2026-11-14 (S5): The call ends through an End Call Phrase (`people who may be able to help`, assistant v4), with no end-call message. Options were an end-call message, an end-call tool, or a phrase. Why: the closing line is said once and the call ends by itself (test call 3). Open: whether the last words are cut off (check by ear). Set by: Andrew.
- 2026-11-14 (S5): The committed sample is built from the raw capture by an allowlist, and the caller number is replaced by the word `REDACTED`, not a fake number. Why: the pattern guard (`tests/unit/guards.test.ts`) forbids phone-shaped text in `docs/samples` and in tests, fake or not. Tests of number stripping build their fake number at runtime. Set by: Andrew.
- 2026-11-14 (S5): Audio recording stays ON in Vapi for now, and the greeting says so. Open: whether to turn it off (Security decides; this project only needs the transcript) and how long Vapi keeps recordings (unknown).
- 2026-11-14: A1 adapts to D1's account model. Two branches defined `organizations` and `regions` with a migration `0000`: A1 (`feat/auth-roles`, memberships with several regions each) and D1 (`feat/database-migrations`, Dillon: one `users` row per staff member with one region and `auth_subject` = Better Auth `user.id`). `main` already follows D1 (`lib/auth/user-session.ts`, PR #21). Options were A1 adapts to D1, or D1 adopts memberships. Decided by: the humans. Trade-off: one region per user for now. Plan: D1 merges first. A1 then keeps only its Better Auth parts (its 4 tables, server config, `/api/auth` allowlist, rate limit, session cleanup, `drizzle.config.ts` fix) as a new migration on top of D1, uses `sessionFromUser`, and applies AC-5 to `users.role`.
- 2026-11-14 (S6): D3 stores **no transcript** in P0 (the transcript column stays null). Why: red line 3 (no personal caller data) conflicts with spec section 10 (a volunteered name "may appear in the transcript"), and scrubbing cannot remove names. Still unknown: how long Vapi keeps its own copy of the call (audio recording is ON) and its transcript (spec section 12, unknowns 2 and 10). Decided by: the humans.
- 2026-11-14 (S6): `passed_on` back to `open` is allowed, but only as a new status-history row that a human triggers (history is never overwritten). This is a **spec change** (spec section 10 and DB-3 do not list it) and needs human approval in the S6 PR. Decided by: the humans.
- 2026-11-14 (S6): Clearing "needs review" is P0 if it is one simple button with a history entry. If Backend or Frontend says it is more than that, it moves to P1 and the PR says so. Decided by: the humans.
- 2026-11-14 (S6 gate): The S6 plan passed the agreement gate 5 of 5 (all with notes, no dissent, no red line cited), and the review round ended with all four reviewers at PASS after fixes. Reason codes are now seven (`malformed_payload`, `no_structured_data`, `processing_error`, `unusable_location`, `ambiguous_match`, `invalid_fields`, `not_confirmed`). Clearing "needs review" is P0 (Frontend and Backend: one button, one POST, one history row). Details in `docs/reviews/S6.md`. Pending human approval in the PR: the `passed_on` to `open` spec change.
- 2026-11-14: UI style guide (docs/style-guide.md) and design boards (docs/design/) adopted. Tokens live in app/tokens.css (prefix --ww-), loaded in app/layout.tsx with IBM Plex through next/font/google (fetched at build time, so the build needs internet access). npm run check:hex fails on raw hex in app/, components/ and lib/ outside tokens.css; three existing files are exempt until their screens move to tokens. Why: one visual system, and color never the only signal.
- 2026-11-14 (contract alignment gate): `docs/contracts.md` now follows the built complaint writes (server actions, `version`, note 1000, passed-on text 200, `passed_on` to `open` P1). Gate 5 of 5 AGREE WITH NOTE, no dissent.
